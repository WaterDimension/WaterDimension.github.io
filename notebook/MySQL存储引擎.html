🗄️ MySQL存储引擎核心知识

一、MySQL体系架构

MySQL的架构可以分为四个层次，像一座四层大楼，每层各司其职：

┌─────────────────────────────────────────────────────┐
│                     连接层                            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │ 本地Socket │ │ TCP/IP  │ │  认证   │ │  权限   │   │
│  │  通信    │ │  通信    │ │  授权   │ │  检查   │   │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘   │
├─────────────────────────────────────────────────────┤
│                     服务层                            │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │ SQL接口  │ │  查询缓存 │ │ 分析器  │ │ 优化器  │   │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘   │
│  ┌─────────────────────────────────────┐           │
│  │     内置函数、存储过程、触发器        │           │
│  └─────────────────────────────────────┘           │
├─────────────────────────────────────────────────────┤
│                     引擎层                            │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐   │
│  │   InnoDB    │ │   MyISAM    │ │   Memory    │   │
│  └─────────────┘ └─────────────┘ └─────────────┘   │
├─────────────────────────────────────────────────────┤
│                     存储层                            │
│  ┌─────────────────────────────────────┐           │
│  │  文件系统：数据、索引、日志、binlog  │           │
│  └─────────────────────────────────────┘           │
└─────────────────────────────────────────────────────┘

1.1 连接层

最上层是一些客户端和连接服务，主要完成：

  • 连接处理（本地socket、TCP/IP通信）
  • 认证授权
  • 安全方案（SSL）
  • 线程池管理

💡 每一句话：这里是MySQL的"门卫"，负责接待来访者并检查身份。

1.2 服务层

第二层是MySQL的核心服务层，负责：

  • SQL接口：接收并执行SQL语句
  • 查询缓存：缓存查询结果（注意：MySQL 8.0已移除）
  • 分析器：词法分析、语法分析，生成解析树
  • 优化器：选择最优执行计划（决定表的查询顺序、索引使用等）
  • 内置函数、存储过程、触发器、视图等跨存储引擎的功能

💡 一句话：这里是MySQL的"大脑"，负责理解指令并规划执行方案。

1.3 引擎层

存储引擎层，真正负责数据的存储和提取：

  • 通过API和服务层通信
  • 不同的存储引擎有不同的功能特性
  • 索引实现在这一层
  • 插件式架构：可以根据业务需求灵活选择

💡 一句话：这里是MySQL的"心脏"，真正的数据存储和读取核心。

1.4 存储层

数据存储层，将数据存储在文件系统上：

  • 数据文件
  • 索引文件
  • 日志文件（redolog、undolog、binlog等）
  • 错误日志、慢查询日志等

💡 一句话：这里是MySQL的"仓库"，实际存放数据的地方。

二、存储引擎介绍

2.1 什么是存储引擎？

存储引擎就是存储数据、建立索引、更新/查询数据等技术的实现方式。

🚗 类比：就像发动机是汽车的核心，存储引擎是MySQL数据库的核心。直升机不能用舰载机的引擎，不同的业务场景也需要选择合适的存储引擎。

重要特性：

  • 存储引擎是基于表的，不是基于库的
  • 也称为表类型
  • 创建表时可以指定，不指定则用默认

2.2 存储引擎操作

查看当前数据库支持的存储引擎

SHOW ENGINES;

创建表时指定存储引擎

CREATE TABLE 表名 (
    字段1 字段1类型 [COMMENT 字段1注释],
    ...
    字段n 字段n类型 [COMMENT 字段n注释]
) ENGINE = INNODB [COMMENT 表注释];

查看表的存储引擎

-- 查看建表语句（会显示存储引擎）
SHOW CREATE TABLE account;

-- 默认存储引擎：InnoDB

示例：创建不同存储引擎的表

-- 创建MyISAM引擎的表
CREATE TABLE my_myisam (
    id INT,
    name VARCHAR(10)
) ENGINE = MyISAM;

-- 创建Memory引擎的表
CREATE TABLE my_memory (
    id INT,
    name VARCHAR(10)
) ENGINE = Memory;

三、三大主流存储引擎详解

3.1 InnoDB（默认存储引擎）

📌 介绍

InnoDB是一种兼顾高可靠性和高性能的通用存储引擎，从MySQL 5.5之后成为默认存储引擎。

⭐ 特点

  • ✅ 支持事务（ACID模型）
  • ✅ 行级锁：提高并发访问性能
  • ✅ 支持外键：保证数据的完整性和正确性

📁 文件结构

  • xxx.ibd：每张表对应一个表空间文件，存储：
    • 表结构（frm-早期版本 / sdi-8.0版本）
    • 数据
    • 索引
-- 查看innodb_file_per_table参数
SHOW VARIABLES LIKE 'innodb_file_per_table';
-- 开启时，每张表对应一个ibd文件

🔧 小工具：可以使用 ibd2sdi 命令从ibd文件中提取sdi信息（包含表结构）

🏗️ 逻辑存储结构

表空间 (Tablespace) ← ibd文件
    ↓
段 (Segment) ← 数据段、索引段、回滚段
    ↓
区 (Extent) ← 每个区1M，包含64个连续页
    ↓
页 (Page) ← 磁盘管理最小单元，默认16KB
    ↓
行 (Row) ← 数据按行存放
层级 说明
表空间 最高层，ibd文件就是表空间
段 数据段、索引段、回滚段，引擎自动管理
区 单元结构，每个区1M = 64个连续页
页 磁盘管理最小单元，默认16KB
行 面向行的存储，包含隐藏字段

3.2 MyISAM（早期默认）

📌 介绍

MySQL早期的默认存储引擎，现在仍被广泛使用。

⭐ 特点

  • ❌ 不支持事务
  • ❌ 不支持外键
  • ✅ 支持表锁（不支持行锁）
  • ✅ 访问速度快

📁 文件结构

文件 存储内容
xxx.sdi 表结构信息
xxx.MYD 数据（MY Data）
xxx.MYI 索引（MY Index）

3.3 Memory（内存引擎）

📌 介绍

数据存储在内存中的引擎，通常用作临时表或缓存。

⭐ 特点

  • ✅ 数据存放在内存中
  • ✅ 默认Hash索引
  • ❌ 断电数据丢失
  • ❌ 表大小受限（受内存限制）

📁 文件结构

  • xxx.sdi：只存储表结构信息
  • 数据：运行时在内存中，不持久化

五、面试必问：InnoDB vs MyISAM

Q：InnoDB引擎与MyISAM引擎的区别？

核心三大区别

对比项 InnoDB MyISAM
① 事务支持 ✅ 支持事务（ACID） ❌ 不支持事务
② 锁机制 ✅ 行锁 + 表锁 ❌ 仅表锁
③ 外键支持 ✅ 支持外键 ❌ 不支持外键

扩展区别（加分项）

对比项 InnoDB MyISAM
存储文件 .ibd（数据和索引一起） .MYD（数据）、.MYI（索引）
崩溃恢复 ✅ 支持（通过redolog） ❌ 容易损坏
MVCC ✅ 支持 ❌ 不支持
全文索引 5.6后支持 支持
缓存 缓存数据+索引 只缓存索引

六、如何选择存储引擎？

选择原则

根据应用系统的特点选择合适的存储引擎，复杂系统可以组合使用多种引擎。

场景推荐

🎯 InnoDB（默认首选）

  • 适用场景：
    • 对事务完整性要求高
    • 并发条件下要求数据一致性
    • 包含大量更新、删除操作
  • 典型应用：订单系统、金融系统、用户中心

🎯 MyISAM

  • 适用场景：
    • 读操作和插入操作为主
    • 很少更新和删除
    • 对事务和并发要求不高
  • 典型应用：数据仓库、日志系统、报表系统

🎯 Memory

  • 适用场景：
    • 临时表、缓存
    • 需要极快访问速度
    • 数据可以丢失
  • 典型应用：会话管理、中间计算结果缓存

七、一句话总结

InnoDB = 事务 + 行锁 + 外键（全能选手）
MyISAM = 高速读写 + 表锁（读多写少专用）
Memory = 内存存储 + Hash索引（临时工）
